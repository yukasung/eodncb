# ประเด็นที่ต้องยืนยัน

รายการต่อไปนี้มาจากความต่างภายในเอกสารและระหว่างเอกสาร ยังไม่ได้แก้ต้นฉบับหรือสรุปแทนเจ้าของกฎ ควรบันทึกคำตอบ ผู้ยืนยัน และวันมีผล ก่อนนำไปพัฒนาและกำหนด expected result

| ID | ประเด็น | หลักฐานและผลกระทบ | คำตอบที่ต้องได้ |
| --- | --- | --- | --- |
| Q01 | ใช้ Mapping ใด | S05 ใช้ EOM, S07 ใช้ TEMPDWHCBS และ default หลายค่า | แหล่ง authoritative แยกตามกลุ่มลูกค้าและงวด |
| Q02 | กลุ่มลูกหนี้จ่ายเคลม | S05 ระบุ F แต่ S11 ระบุ E1/E2/F | กฎแบ่งกลุ่มและ priority ของ Grade กับ Claim Pay Date |
| Q03 | DFD แบบ T+1 | คำอธิบายกับตัวอย่างใน S05 บางจุดแสดงวันต่างกัน | สูตรรวม/ไม่รวมวันแรก และตัวอย่างที่อนุมัติ |
| Q04 | Amount Past Due ที่ 90/91 วัน | ข้อความตั้งแต่ 91 วันกลับมีเงื่อนไข DPD น้อยกว่า 90 และช่วง 1–90 ใช้เงื่อนไขน้อยกว่า 90 | เงื่อนไขรวม boundary และนิยามยอดค่างวดสะสม |
| Q05 | ไม่ทำ TDR เริ่มส่งยอดค้างเมื่อใด | ระบุทั้ง DPD ตั้งแต่ 1 วันและ DPD มากกว่า 30 | จุดเริ่มรายงานยอดค้างที่แน่นอน |
| Q06 | Close Date / NULL | หลายข้อเขียน “ไม่มีวันปิดบัญชี” แต่กำกับ != NULL และบางข้อ “มีวันปิดบัญชี” ใช้ == NULL | truth table ของ NULL/sentinel/วันที่จริง |
| Q07 | นิยาม TDR Date | S11 แยกระบบเดิมกับเฟส 2; Mapping ใช้วันที่ล่าสุดทั้ง active/inactive | ฟิลด์ต้นทาง วันมีผล และผลเมื่อมี Upfront |
| Q08 | Priority เมื่อหลายเงื่อนไข | TDR Set Zero, คดี, พักชำระ, ปิดบัญชี อาจเกิดในงวดเดียวกัน | decision table ที่ครอบคลุมกรณีซ้อน |
| Q09 | สถานะ 21 | กฎให้ส่งต่อเฉพาะประวัติเดิม แต่ remark UAT บางรายการอิงช่วง DFD | วิธีตรวจประวัติและข้อห้ามกลับเข้า 21 |
| Q11 | Format วันที่ | Mapping ระบุ eff_date/as_of_date เป็น พ.ศ. แต่สไลด์ field นำส่งระบุ ค.ศ. YYYYMMDD | รูปแบบราย field ในแต่ละชั้นและแต่ละไฟล์ |
| Q12 | ชื่อฟิลด์/ตาราง | มี owneship_indicator, date_account_opend, DateEndOfMonth | DDL และชื่อ output contract ที่ถูกต้อง |
| Q13 | เกณฑ์หยุดส่ง | สูตร 5 ปี 90 วัน การปลดล้ม 2 ปี และการกลับมาปิดบัญชีภายใน 36 เดือน | การนับวัน/ปี การปัดงวด และเหตุผลหยุดส่ง |
| Q14 | สถานะ 33/42 | S01/S05 มีเงื่อนไขเพิ่มจากรายการสถานะต้น S11 | ขอบเขตใช้งาน Consumer/Commercial และเหตุการณ์ที่ trigger |
| Q15 | Borrower count | ชื่อ Number of co-borrower แต่คำอธิบายรวมผู้กู้หลักด้วย | จำนวนผู้กู้ร่วมล้วนหรือจำนวนผู้กู้ทั้งหมดในแต่ละ format |
| Q16 | Member Master | ต้องแยก environment และ active ตาม ReportType | ค่าแต่ละ environment และกฎห้าม active ซ้ำ |
| Q17 | รายงานข้ามปี | S09 ให้ย้าย schema/เปลี่ยนชื่อ HIS แต่ไม่ระบุ dependency | runbook, rollback, permission และการ query ประวัติ |
| Q18 | ความพร้อม UAT | มี In-Progress, Failed และ Re Check With User | ผลทดสอบที่ผู้ใช้รับรองพร้อมวันและเวอร์ชันข้อมูล |

## วิธีปิดประเด็นที่เสนอ

เพิ่มผลตัดสินใต้ ID เดิมโดยเก็บข้อความเดิมไว้ ระบุผู้อนุมัติ วันที่มีผล ตัวอย่าง input/output และ TestCaseID ที่รองรับ จากนั้นปรับเอกสารกฎ Mapping และกรณีทดสอบให้ตรงกัน

**แหล่งอ้างอิง:** S01, S02 และ S05–S11 โดยเฉพาะ S05 และ S11 ดู [ทะเบียนเอกสาร](/sources)
