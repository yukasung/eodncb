# คำศัพท์โครงการ

## บสย. คืออะไร

**บสย.** ย่อมาจาก **บรรษัทประกันสินเชื่ออุตสาหกรรมขนาดย่อม** ภาษาอังกฤษใช้ **Thai Credit Guarantee Corporation (TCG)** ทำหน้าที่ค้ำประกันสินเชื่อเพื่อช่วยให้ผู้ประกอบการ SMEs ที่มีศักยภาพแต่หลักประกันไม่เพียงพอเข้าถึงสินเชื่อจากสถาบันการเงินได้

ในภาพการทำงานของโครงการ **สถาบันการเงินเป็นผู้ให้กู้ ผู้ประกอบการเป็นผู้กู้ และ บสย. เป็นผู้ค้ำประกันตามเงื่อนไข** หนังสือค้ำประกันเรียกว่า LG (หนังสือค้ำประกัน) เมื่อมีการจ่ายค่าประกันชดเชยหรือจ่ายเคลมตามเงื่อนไข เอกสารโครงการจะติดตามยอดหนี้และการชำระต่อ บสย. ด้วย จึงมีข้อมูลทั้งกลุ่มภาระค้ำประกันและกลุ่มลูกหนี้จ่ายเคลม

ตัวอย่างสมมติ: ผู้ประกอบการขอกู้จากธนาคารและมี บสย. ค้ำประกัน ระบบจึงต้องเก็บว่า LG (หนังสือค้ำประกัน) ใดเกี่ยวข้องกับผู้กู้คนใด มีภาระค้ำเท่าใด และต่อมามีการจ่ายเคลม ชำระหนี้ หรือทำ TDR หรือไม่ เพื่อจัดทำข้อมูลรายงานตามเงื่อนไข

บทบาทการค้ำประกันอ้างอิง [กระทรวงอุตสาหกรรม](https://www.industry.go.th/th/secretary-of-industry/13972) ส่วนรายละเอียด LG (หนังสือค้ำประกัน) และลูกหนี้จ่ายเคลมอ้างอิงเอกสารโครงการ S05/S11

## NCB (เครดิตบูโร) คืออะไร

**NCB (เครดิตบูโร)** ย่อมาจาก **National Credit Bureau** คือ **บริษัท ข้อมูลเครดิตแห่งชาติ จำกัด** ทำหน้าที่รวบรวมข้อมูลบัญชีสินเชื่อและประวัติการชำระสินเชื่อของบุคคลธรรมดาและนิติบุคคลจากสถาบันการเงินและบริษัทที่เป็นสมาชิก อ้างอิง [ธนาคารแห่งประเทศไทย](https://www.bot.or.th/th/satang-story/managing-debt/creditbureau.html)

**จำง่าย: สมาชิกส่งข้อมูล → NCB (เครดิตบูโร) รวบรวมประวัติเครดิต → สถาบันการเงินใช้ประกอบการพิจารณาสินเชื่อ**

ในเอกสารโครงการ “รายงาน NCB (เครดิตบูโร)” หมายถึงชุดข้อมูลที่ บสย. เตรียมนำส่ง เช่น ตัวตนผู้กู้ เลข LG (หนังสือค้ำประกัน) ภาระค้ำหรือยอดหนี้ สถานะบัญชี DPD และ TDR จึงต้องแยกให้ออกระหว่าง **NCB (เครดิตบูโร) ซึ่งเป็นหน่วยงานผู้รับข้อมูล** กับ **ระบบหรือรายงาน NCB (เครดิตบูโร) ภายในโครงการ**

## EOD คืออะไร

**EOD = End of Day** หมายถึงข้อมูล ณ สิ้นวัน หรือกระบวนการประมวลผลปิดวัน ในโครงการนี้ใช้กับข้อมูลรายวัน เช่น ยอดหนี้คงเหลือ วันที่ชำระล่าสุด และจำนวนวันค้างชำระของบัญชี

ตัวอย่างสมมติ: ลูกหนี้ชำระเงินวันที่ 15 พฤษภาคม ข้อมูล EOD ของวันนั้นจะแสดงภาพข้อมูลหลังนำรายการที่อยู่ในรอบปิดวันมาประมวลผลแล้ว ทั้งนี้เวลา cutoff และชื่อ job จริงยังต้องยืนยันจากระบบ

## EOM คืออะไร

**EOM = End of Month** หมายถึงข้อมูล ณ สิ้นเดือน หรือกระบวนการประมวลผลปิดเดือน ใช้เป็นภาพข้อมูลของงวดเดือน เช่น ข้อมูล ณ วันที่ 31 พฤษภาคม สำหรับจัดทำรายงานประจำเดือน

เอกสาร S05 ใช้ `DataEndOfMonth` เป็นแหล่ง Mapping หลัก **ยอดคงเหลือสิ้นเดือนไม่ใช่ผลบวกของยอดคงเหลือทุกวัน** แต่เป็นยอด ณ วันสิ้นเดือนตามนิยามข้อมูล ส่วนข้อมูลบางประเภทอาจใช้การสะสมหรือกฎเฉพาะ จึงต้องดูเป็นรายฟิลด์

## TDR คืออะไร

**TDR = Troubled Debt Restructuring** หมายถึง **การปรับปรุงโครงสร้างหนี้ที่มีปัญหา** เป็นการตกลงปรับเงื่อนไขชำระหนี้ให้เหมาะกับความสามารถของลูกหนี้ เช่น ปรับจำนวนเงินต่องวด อัตราดอกเบี้ย หรือระยะเวลาชำระ ไม่ได้หมายถึงการยกหนี้ และไม่เหมือนกับการพักชำระหนี้ทุกกรณี

ในเอกสารโครงการ `TDR Date` ใช้แทนวันที่ทำหรือเริ่มแผนปรับโครงสร้างหนี้ตามนิยามที่ต้องยืนยัน ส่วน `TDR Code` เป็นรหัสที่ใช้รายงานประเภทการปรับโครงสร้างหนี้ การมี TDR อาจมีผลต่อ DFD, DPD, Amount Past Due และสถานะบัญชี โดยเฉพาะกฎ Set Zero ในเดือนที่เข้าเงื่อนไข ดู [กฎ DFD DPD และ TDR](/business-rules)

คำแปลและชื่อเต็มอ้างอิงแนวนโยบายเรื่องการปรับปรุงโครงสร้างหนี้ของ [ธนาคารแห่งประเทศไทย](https://www.bot.or.th/content/dam/bot/fipcs/documents/FPG/2566/ThaiPDF/25660231.pdf) ส่วนวิธีคำนวณในโครงการอ้างอิง S05 และ S11

## ทั้งสี่คำเกี่ยวข้องกันอย่างไร

บสย. จัดทำข้อมูลการค้ำประกันและลูกหนี้เพื่อนำส่ง NCB (เครดิตบูโร) ซึ่งเป็นผู้รวบรวมข้อมูลเครดิตจากสมาชิก โดย EOD แสดงสถานะข้อมูลรายวัน ส่วนข้อมูล EOM ช่วยมองสถานะ ณ สิ้นเดือน จากนั้นระบบเลือกแหล่งข้อมูลตาม pipeline ที่ยืนยันแล้ว คัดรายการและแปลงฟิลด์เป็นรายงานของ บสย. เพื่อนำส่ง NCB (เครดิตบูโร)

ความสัมพันธ์นี้อธิบายบทบาทของข้อมูล ยังไม่ยืนยันว่าระบบทุกส่วนต้องรัน EOD ต่อ EOM เสมอ เพราะเอกสารมีทั้ง Mapping ต้นทางรายวัน EOM และ DWH ดู [กระบวนการและแหล่งข้อมูล](/data-flow)

## คำศัพท์อื่นที่ใช้ในเอกสาร

| คำ | ความหมายในเอกสาร |
| --- | --- |
| บสย. / TCG | บรรษัทประกันสินเชื่ออุตสาหกรรมขนาดย่อม ผู้ค้ำประกันสินเชื่อและหน่วยงานจัดทำรายงานในโครงการ |
| NCB (เครดิตบูโร) | National Credit Bureau หรือบริษัท ข้อมูลเครดิตแห่งชาติ จำกัด ผู้รับข้อมูลเครดิตจากสมาชิก |
| EOD | End of Day ข้อมูลสิ้นวัน |
| EOM | End of Month ข้อมูลสิ้นเดือน |
| LG (หนังสือค้ำประกัน) · Letter of Guarantee | หนังสือค้ำประกันสินเชื่อ; เลข LG (หนังสือค้ำประกัน) ใช้อ้างอิงรายการค้ำประกันและใช้เป็นเลขบัญชีใน Mapping ดู [คำอธิบายและตัวอย่าง](/credit-reporting#lg-คืออะไร) |
| CIF | รหัสลูกค้า ตรงกับ customer_code |
| Consumer | ข้อมูลบุคคลธรรมดา |
| Commercial Profile | ข้อมูลระบุตัวตนนิติบุคคล |
| Commercial Report / Credit | ข้อมูลสินเชื่อและประวัติการชำระของนิติบุคคล |
| DCS | ระบบบริหารจัดการลูกหนี้ที่อ้างในเอกสาร |
| Magic | ระบบต้นทางลูกค้าที่อ้างในตารางรวมฟิลด์ |
| DWH | Data Warehouse |
| DFD | Default Date วันเริ่มผิดนัดชำระ |
| DPD | Days Past Due จำนวนวันค้างชำระ |
| DPD Code | รหัสที่ Mapping จากจำนวนวันค้าง ไม่ใช่จำนวนวันจริง |
| TDR | Troubled Debt Restructuring การปรับปรุงโครงสร้างหนี้ที่มีปัญหา ดูคำอธิบายหัวข้อ TDR คืออะไร |
| Claim Pay Date | วันที่ บสย. จ่ายค่าประกันชดเชย |
| Current Balance / Amount Owed / Outstanding | ยอดหนี้คงเหลือตามนิยามฟิลด์และกรณีธุรกิจ |
| Amount Past Due | ยอดหนี้ที่เกินกำหนดชำระ |
| As Of Date | วันที่ข้อมูลมีผลในงวดรายงาน |
| TUDF | TransUnion Data Format รูปแบบจัดข้อมูลนำส่งเครดิต; ในโครงการใช้กับ Consumer ดูคำอธิบายในหน้าภาพรวม |
| Catalog ID | รหัสอ้างอิง เช่น สถานะบัญชีหรือ DPD สำหรับ Commercial |
| SIT / UAT / PROD | สภาพแวดล้อมทดสอบระบบ ทดสอบผู้ใช้ และใช้งานจริง |
| Set Zero | การเคลียร์ค่าค้างชำระตามเหตุการณ์ เช่น เดือนเข้า TDR |
| Upfront | การชำระก่อนงวดปกติ ซึ่ง S11 แยกจากงวดเดือนที่ 1 ของ TDR เฟส 2 |

**แหล่งอ้างอิง:** คำที่ใช้ใน S01, S02 และ S05–S11 ดู [ทะเบียนเอกสาร](/sources)
